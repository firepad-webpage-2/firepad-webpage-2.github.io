## Bridging the Gap Between Narrative and Rigor in AI Economics

Large Language Models (LLMs) have demonstrated a remarkable ability to generate coherent and professional-sounding economic reports. However, in the field of economics, narrative fluency is insufficient. A statement such as "inflation is likely to persist" is only analytically useful if it can be traced back to specific macroeconomic mechanisms, empirical data, and formal mathematical models. Existing LLM-based approaches often struggle with this "grounding" requirement, sometimes hallucinating numerical data or failing to link qualitative claims to established economic theory.

The "AI Economist Agent" framework addresses this by moving beyond simple text generation. It introduces an agentic system that uses Knowledge Graphs (KGs) and Retrieval-Augmented Generation (RAG) to ensure that every claim in an economic report is grounded in a verifiable model execution. The framework distinguishes between textual evidence and mathematical models, ensuring that numerical outputs are computed by external tools rather than being predicted by the language model itself.

## Core Principles of Model-Grounded Analysis

The central innovation of this framework is the separation of narrative generation from numerical computation. Standard RAG systems typically retrieve unstructured text snippets to inform an LLM. In contrast, this framework employs a "model-grounded" approach where the LLM acts as an orchestrator. It performs four distinct roles: planning the analysis, retrieving relevant information, selecting the appropriate mathematical model, and finally, explaining the results.

The system is built on three architectural pillars:
1.  **Separation of Knowledge Objects:** The system stores textual evidence (e.g., historical economist reports) and formal mathematical model specifications (e.g., equations for a Dynamic Stochastic General Equilibrium model) as distinct entities in a Knowledge Graph.
2.  **Explicit Model Selection:** Instead of the LLM attempting to "reason" through numbers, it uses the Knowledge Graph to find an "Implementation Function"—a pre-approved computational routine—that matches the economic scenario.
3.  **Traceable Execution:** Quantitative claims are only generated *after* a model has been executed. The results of the computation are written back into the Knowledge Graph, creating a permanent, auditable record of the analysis.

For a given economic scenario $s$, the final report is generated by synthesizing several components:
$$(s, E_s, P_{pre\_s}, C_s, r_s, m_s, O_s, P_{post\_s})$$
where $E_s$ represents retrieved text evidence, $P_{pre\_s}$ are the initial graph paths, $C_s$ is the model context, $r_s$ is the execution request, $m_s$ is the record of the model run, $O_s$ is the actual output data, and $P_{post\_s}$ are the post-execution graph paths.

## Knowledge Graph and Temporal Design

The framework utilizes a typed, directed Knowledge Graph to organize economic reality. This graph is essential for managing the complexity of economic data, which includes not just facts, but also relationships between variables and the models that describe them.

Key node types in the graph include:
-   **Economic Task Nodes:** These define the `Scenario` being analyzed (e.g., "CRE Refinancing Stress") and the specific `Shock` or `VariableConcept` involved.
-   **Model Catalog:** This includes `ModelSpecification` (the theoretical equations), `ModelAssumption`, and `ModelDocument`. Crucially, these are linked to `ImplementationFunction` nodes, which are the actual Python or R routines that can be executed.
-   **Execution Objects:** Once a model is run, the graph records a `ModelRun` node, which links to `ForecastOutcome` and `ModelOutputPoint` nodes. This allows the system to "know" exactly which numbers came from which model run.

The system also incorporates a sophisticated temporal design. Economic facts have "observation times" (when the data was recorded) and "validity windows" (the period for which a claim is relevant). By representing these as `TemporalFact` nodes, the agent can avoid using outdated data or applying a model to the wrong historical context.

## The Agentic Workflow

The AI Economist Agent operates through a multi-step workflow designed to mirror the process a human economist would follow:

1.  **Planning:** A planner agent analyzes the scenario to determine the objectives. For example, if the scenario involves a rise in interest rates, the planner identifies that it needs to look for models relating interest rates to consumption or investment.
2.  **Retrieval:** The system performs a dual retrieval. It uses standard RAG to find text evidence and GraphRAG to find structural connections between variables and models.
3.  **Model Selection and Execution:** A model-selection agent chooses the best `ModelSpecification` from the graph. It then generates a structured request $r_s$ that triggers an external computational layer. This layer runs the math and returns the raw data $O_s$.
4.  **Reporting:** Finally, a generation agent takes all this information—the textual evidence, the model specifications, and the hard numbers—to write a report that explains *why* the model produced those specific results.

## Application 1: U.S. Inflation and Fed Policy

The first test of the framework involved analyzing a scenario of persistent services inflation and gradual labor-market cooling. The goal was to see if the agent could select a relevant model and generate a report grounded in its output.

The agent successfully selected a "DSGE-lite" model (a simplified version of a standard macroeconomic model). The computational layer executed the model, producing a path for variables such as headline inflation, the Federal funds rate, and the output gap.

## Significance of the Framework

The AI Economist Agent represents a shift in how AI is applied to high-stakes analytical fields. By enforcing a strict separation between "the voice" (the LLM) and "the logic" (the mathematical model), the framework addresses the primary criticism of LLMs in finance and economics: the lack of transparency.

This research has several major implications:
-   **Traceability:** Every number in a report can be traced back to a specific `ModelRun` and `ModelSpecification`. If a forecast is questioned, an analyst can inspect the exact code and parameters that produced it.
-   **Reliability:** By using pre-defined implementation functions, the system eliminates the risk of the LLM performing incorrect arithmetic or misinterpreting mathematical formulas.
-   **Agentic Orchestration:** It demonstrates that LLMs are highly effective at the "meta-task" of research—planning, selecting tools, and synthesizing results—even if they should not be trusted to perform the underlying computations themselves.

In conclusion, this framework provides a blueprint for building "model-grounded" AI agents. While the experiments used synthetic data and simplified models, the architecture is designed to scale to the complex, multi-model environments used by central banks and financial institutions. It transforms AI from a simple text generator into a rigorous research assistant capable of verifiable economic analysis.
