## Foundations of Constraint-Based Causal Discovery

Causal discovery represents a shift in data analysis from identifying mere associations to uncovering the underlying mechanisms that govern a system. While correlation measures how two variables move together, causal discovery seeks to determine if one variable directly influences another. Constraint-based algorithms, such as the Peter-Clark (PC) and Fast Causal Inference (FCI) algorithms, are a prominent family of methods used to infer these relationships from observational data.

*{fig:causal-structures-represented-as-graphs}: An example of a causal graph where nodes represent variables and edges represent direct causal influences. The shaded node $X$ represents the variable of interest within its local neighborhood.*

These algorithms rely on the mapping between the statistical properties of the data and the structural properties of a Directed Acyclic Graph (DAG). At the heart of this mapping is the concept of conditional independence. A constraint-based algorithm operates by systematically querying a statistical "engine"—the Conditional Independence (CI) test—to decide whether an edge should exist between two variables $X$ and $Y$, potentially given a set of other variables $Z$. The fundamental goal is to identify the set of all $I(X, Y | Z) \text{ where } Z \subseteq V \setminus \{X, Y\}$, where $V$ is the set of all observed variables.

The reliability of the entire causal discovery process hinges on three core assumptions. First, the Causal Markov Condition assumes that each variable is independent of its non-descendants given its direct causes (parents). Second, Faithfulness assumes that all statistical independencies observed in the data are due to the structure of the causal graph, rather than accidental cancellations of effects. Finally, the Causal Sufficiency assumption (often relaxed in algorithms like FCI) posits that all common causes of observed variables are themselves observed. If these assumptions hold and the CI tests provide perfect information, constraint-based algorithms are guaranteed to recover the correct Markov equivalence class of the underlying causal structure.

## The Role of Conditional Independence Tests

In practice, we do not have perfect information about the underlying distribution; we only have a finite sample of data. This makes the choice of CI test the most critical design decision in the discovery pipeline. The CI test acts as a gatekeeper: if the test incorrectly identifies independence, a true causal link is deleted (a Type II error); if it incorrectly identifies dependence, a spurious link is added (a Type I error).

Constraint-based discovery typically proceeds in two main phases:
1.  **Skeleton Discovery:** Starting with a complete undirected graph, the algorithm removes edges between variables if a CI test finds them to be independent given some conditioning set $Z$. The algorithm usually starts with $|Z| = 0$ (marginal independence) and incrementally increases the size of $Z$.
2.  **Edge Orientation:** Once the skeleton is fixed, the algorithm uses the information about which sets $Z$ rendered variables independent to orient the remaining edges. A key step is identifying v-structures, such as $A \to B \leftarrow C$, where $A$ and $C$ are independent but become dependent when conditioning on $B$.

## A Taxonomy of CI Test Families

The survey categorizes CI tests into six primary families, each with distinct statistical assumptions and computational profiles.

### Partial-Correlation–Based Tests
The most common CI test for continuous data is Fisher’s Z test. It assumes that the variables follow a multivariate normal distribution and that the relationships between them are linear. Under these conditions, conditional independence is equivalent to a vanishing partial correlation:
$$\rho_{XY \cdot Z} = 0$$
The test utilizes a transformation to achieve a near-normal distribution:
$$z = \frac{1}{2} \ln \left( \frac{1 + \hat{r}_{XY \cdot Z}}{1 - \hat{r}_{XY \cdot Z}} \right)$$
Fisher's Z is highly efficient, but its performance degrades significantly if the data is non-Gaussian or if the relationships are nonlinear.

### Contingency-Table–Based Tests
For categorical data, tests like Pearson’s $\chi^2$ or the likelihood-ratio $G^2$ test are used. The $G^2$ statistic is defined as:
$$G^2 = 2 \sum_{i,j,k} n_{ijk} \ln \left( \frac{n_{ijk}}{m_{ijk}} \right)$$
where $n_{ijk}$ are the observed counts and $m_{ijk}$ are the expected counts under the null hypothesis of independence. These tests are $O(n) \text{ per test}$ but suffer from "sparsity" issues. As the size of the conditioning set $Z$ increases, the number of cells in the contingency table grows exponentially, leading to many cells with zero counts and making the asymptotic $\chi^2$ distribution an unreliable approximation.

### Regression and Machine Learning-Based Tests
Regression-based tests model $X$ as a function of $Z$ and check if adding $Y$ to the model improves the fit. While flexible, these often only test for conditional mean independence. More modern approaches use Double Machine Learning (DML) or the Generalised Covariance Measure (GCM). These methods use flexible machine learning models (like Random Forests or Neural Networks) to regress $X$ on $Z$ and $Y$ on $Z$, then test for independence between the residuals. These are model-agnostic but computationally demanding.

### Nonparametric and Kernel Tests
When the functional form of the relationship is unknown, nonparametric tests like the Kernel Conditional Independence (KCI) test or nearest-neighbor methods (like CMIknn) are employed. KCI maps the data into a high-dimensional feature space where linear methods can detect nonlinear dependencies. While powerful, KCI has a high computational cost of $O(n^3)$. Randomized approximations like RCoT and RCIT reduce this to $O(n d_f^2)$, making them more feasible for larger datasets.

## Statistical Challenges and Graph-Level Errors

A major finding of the survey is the propagation of errors from the test level to the graph level. The "power" of a statistical test—its ability to correctly detect a dependence—decreases as $|Z| \to \infty$. In causal discovery, this is a pervasive problem because the algorithm must test larger and larger conditioning sets to prune the graph.

When a CI test lacks power, it tends to incorrectly return "independent." This Type II error leads the algorithm to remove a true causal edge. Even worse, if this incorrect independence is used during the orientation phase, the algorithm may fail to identify v-structures or orient edges in the wrong direction, leading to an entirely different causal interpretation. Conversely, Type I errors (false positives) introduce spurious edges that complicate the graph and may lead to cycles or inconsistent orientations.

## Decision Guidelines for Practitioners

Selecting the right CI test is a trade-off between statistical power, computational budget, and data characteristics. The survey provides heuristic decision trees to guide this choice.

### Continuous Data
For continuous variables, the primary question is whether the data is linear and Gaussian. If yes, Fisher's Z is the optimal choice due to its speed. If the data is nonlinear, the choice depends on the computational budget and expected conditioning set depth.

### Categorical and Mixed Data
Categorical data is traditionally handled by $G^2$ tests, but practitioners must be wary of large conditioning sets. Mixed-type data (a combination of continuous and categorical variables) remains a challenge. Common approaches include discretizing continuous variables—which can destroy information—or using specialized nearest-neighbor or regression-based tests.

## Scalability and Software Implementation

In high-dimensional settings where $p \gg n$ (many variables, few samples), the number of required CI tests grows combinatorially. This necessitates systems-level optimizations. Many libraries now offer parallelized versions of the PC algorithm, and some even provide GPU-accelerated implementations (like cuPC).

The survey notes a discrepancy between the availability of CI tests in R versus Python. R libraries like `pcalg` and `bnlearn` have historically provided a wider range of robust statistical tests. However, Python libraries like `causal-learn` and `Tigramite` are rapidly catching up, particularly in the implementation of kernel-based and machine learning-based CI tests.

## Interpretability and Transparency

One of the greatest strengths of constraint-based causal discovery is its interpretability. Unlike "black-box" models, a constraint-based graph provides an audit trail. For every edge that is missing, the algorithm can specify the exact set $Z$ that rendered the variables independent. For every oriented edge, the algorithm can point to the v-structures or orientation rules that dictated the direction. 

However, this transparency is only as good as the underlying CI test. If a practitioner uses a highly complex machine learning-based test, they may gain statistical power at the cost of being able to explain *why* the test reached a certain conclusion. The survey emphasizes that researchers should report not just the final graph, but also the choice of CI test, the significance level $\alpha$, and the maximum conditioning set size allowed, as these parameters fundamentally shape the resulting causal claims.
