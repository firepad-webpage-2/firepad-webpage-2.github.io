## Understanding Federated Learning with Data Imbalance

Federated Learning (FL) is a decentralized training paradigm where multiple participants, or clients, collaboratively train a machine learning model without sharing their raw data. Instead, clients train models locally and share only the resulting parameter updates with a central server for aggregation. While this preserves privacy, it introduces a major challenge: data heterogeneity. In real-world scenarios, the data held by different clients often follows very different distributions, a phenomenon known as being non-Independent and Identically Distributed (non-IID).

One of the most persistent forms of heterogeneity is data imbalance. This occurs when some classes (majority classes) have many more samples than others (minority or tail classes). In a federated setting, this is doubly complicated: imbalance exists globally across the entire system and locally within each client's dataset. Furthermore, because of privacy constraints, the central server often has no knowledge of the global class distribution, and individual clients may be entirely missing certain classes. This mismatch causes global models to become biased toward majority classes, significantly degrading performance on minority ones.

Current solutions typically focus on "algorithm-level" fixes, such as adjusting loss functions or aggregation methods. However, "data-level" methods—which involve modifying the training data itself—have remained underdeveloped in FL because they usually require knowing the global class distribution to identify which classes need more samples. FedReLa (Federated Re-Labeling) addresses this gap by introducing a data-level approach that does not require global knowledge, extra communication, or architecture changes.

## The Principle of Decision Boundary Shift

To understand how FedReLa works, we must first look at how imbalance affects a model's decision-making. In a standard classification task, a model tries to find a "Bayesian decision boundary" between two classes, $j$ and $\ell$. Ideally, this boundary sits where the probability of a sample belonging to either class is equal. However, when class $\ell$ is much more frequent than class $j$ ($\pi_j \ll \pi_\ell$), the optimal decision boundary $S_{j,\ell}$ shifts.

Mathematically, the boundary is defined by the ratio of class-conditional distributions:

$$
P_j(x)/P_\ell(x) = \pi_\ell/\pi_j
$$

When the majority class prior $\pi_\ell$ is large, the ratio on the right side becomes very high. This forces the decision boundary to intrude deep into the territory of the minority class $j$. Consequently, samples that actually belong to the minority class are frequently misclassified as the majority class because they fall on the "wrong" side of this shifted boundary.

FedReLa's core insight is that we can shift this boundary back by strategically re-labeling some majority class samples as minority class samples. If a client $k$ re-labels samples from class $\ell$ to class $j$ with a certain probability $\rho_{\ell \to j}^{(k)}(x)$, it effectively changes the local class distribution and "pushes" the decision boundary back toward the majority class, creating a fairer model during training.

## The FedReLa Framework: A Step-by-Step Guide

FedReLa acts as a lightweight, local data preprocessor. It is usually executed once during the training process—at a specific round $T_{relabel}$—to re-balance the local datasets. The process follows four key steps.

### 1. Global Model Inference
At the designated re-labeling round, each client receives the current global model $f(\theta_{global}; x)$. The client uses this model to perform a single pass of inference on its entire local dataset $D^{(k)}$. This generates a posterior probability matrix $Q^{(k)}$, where each entry $Q_i^{(k)}$ represents the model's confidence that a specific sample $x_i^{(k)}$ belongs to each possible class.

### 2. Posterior Calibration via Z-Score Standardization
A major problem is that because the global model is already biased, its raw confidence (posterior probability) for minority classes will be naturally very low. If we simply picked the highest probability, we would almost always stick with the majority class. 

To solve this, FedReLa applies **z-score standardization**. For every sample $x_i^{(k)}$ with its original label $y_i^{(k)}$, the client calculates the mean $\mu_i^{(k)}$ and standard deviation $\sigma_i^{(k)}$ of the model's predictions for all samples sharing that same label. The standardized score (z-score) is:

$$
z_i^{(k)} = (Q_i^{(k)} - \mu_i^{(k)}) / \sigma_i^{(k)}
$$

This step recalibrates the scores. Instead of looking at absolute probability, it looks at how much higher a class's score is compared to the average for that specific group of samples. This allows the system to identify minority class features even when the absolute probability is low.

### 3. Normalization and Thresholding
After standardization, the scores are passed through a `tanh` function to map them into a $[0, 1]$ range, creating a re-labeling probability. Two filters are applied here:
*   **Thresholding:** A hyperparameter $\tau$ (e.g., the top 5% of scores) determines a threshold $t_{re}^{(k)}$. Only samples that show a strong relative affinity for another class are considered for re-labeling. This prevents "noisy" or low-confidence re-labeling.
*   **Directional Control:** A reweighting vector $\varpi_j^{(k)}$ is used to ensure that re-labeling only happens *from* majority classes *to* minority classes, preserving the integrity of existing minority samples.

The final re-labeling probability for a sample is:

$$
\max(\tanh(z_i^{(k)} - t_{re}^{(k)}) \odot \varpi_{y_i}^{(k)}, 0)
$$

### 4. Probabilistic Re-labeling
Finally, each client applies these probabilities to its dataset $D^{(k)}$ to create a new, re-labeled dataset $\tilde{D}^{(k)}$. This updated dataset is then used for all remaining local training rounds.

## Unique Contributions and Distinctions

FedReLa differs from existing federated learning methods in several fundamental ways:

*   **Zero Communication Overhead:** Most FL imbalance methods require sharing local class counts or auxiliary information with the server. FedReLa is entirely local. It uses the global model's existing knowledge as a "label re-allocator," meaning no extra data is sent over the network.
*   **Data-Level Intervention:** While most research focuses on changing the *optimizer* (e.g., FedProx) or the *loss function* (e.g., FedLOGE), FedReLa changes the *data*. This makes it a "plug-and-play" module that can be combined with almost any existing FL algorithm.
*   **Handling Class Absence:** In many FL scenarios, a client might have zero samples of a minority class. Traditional synthetic data generation (like SMOTE) fails here because there are no "seed" samples to build from. FedReLa solves this by converting existing majority samples into minority ones based on their feature similarity.
*   **Computational Efficiency:** The re-labeling process is "one-shot." It happens once at $T_{relabel}$ and adds a computational cost equivalent to about one-third of a single training epoch.

## Experimental Results and Performance

The researchers tested FedReLa across multiple benchmark datasets, including Fashion-MNIST, CIFAR-10, CIFAR-100, and the large-scale ImageNet-LT.

### Step-wise and Long-tailed Imbalance
In experiments where a specific percentage of classes were designated as minority (step-wise imbalance), FedReLa significantly boosted accuracy. On CIFAR-100, for example, minority-class accuracy improved by as much as 38.30%. In "long-tailed" settings, where class sizes follow a power-law distribution, FedReLa consistently improved performance for "tail" (rare) classes.

### Robustness to Heterogeneity
The method was tested with varying degrees of data heterogeneity using a Dirichlet distribution parameter $\alpha \in \{0.1, 0.3, 10\}$. At $\alpha = 0.1$ (extreme heterogeneity where many clients lack most classes), FedReLa showed its greatest gains. This confirms that the approach is particularly effective when the data is most fragmented and imbalanced.

### Sensitivity to the Threshold $\tau$
The threshold $\tau$ acts as a "strength" control for re-labeling. As shown in {fig:sensitivity-analysis-of-tau}, increasing $\tau$ leads to more samples being re-labeled, which dramatically increases the accuracy of tail and medium classes. While there is a slight trade-off—very aggressive re-labeling can eventually decrease the accuracy of the original majority (head) classes—a moderate $\tau$ (around 5%) usually provides the best balance, improving overall system accuracy.

## Conclusion

FedReLa provides a practical solution to one of the most difficult problems in decentralized machine learning: how to handle imbalanced data when you cannot see the global distribution. By repurposing the global model to act as an automated data editor, it allows clients to re-balance their own data locally. 

Its ability to function without extra communication and its compatibility with various existing algorithms make it a highly versatile tool. Whether applied to medical imaging (where rare diseases are minority classes) or financial fraud detection (where fraud is a tail event), FedReLa offers a path toward more equitable and accurate federated models without compromising the core privacy principles of the federated learning paradigm.
