## The Integration of Dynamical Systems into Probabilistic Programming

State-space models (SSMs) provide a robust mathematical framework for describing systems that evolve over time. These models are central to various fields, including robotics, economics, and neuroscience, because they allow researchers to explicitly model the internal, hidden mechanics of a system while accounting for noise and measurement error. In a Bayesian context, these models facilitate "system identification"—the process of inferring unknown physical parameters and hidden states from noisy observations.

Despite their utility, implementing advanced inference for SSMs remains a significant engineering challenge. Most sophisticated algorithms, such as specialized Kalman filters or particle filters, are often confined to isolated, custom codebases. This fragmentation creates a barrier for practitioners who wish to apply these methods to new problems or compare different algorithmic approaches within a standard "Bayesian workflow."

`dynestyx` is a probabilistic programming library designed to bridge this gap. Built as an extension to NumPyro, it integrates dynamical systems as first-class citizens within a general-purpose probabilistic programming language (PPL). By doing so, it allows users to separate the high-level specification of a physical model from the low-level details of the inference algorithm, making state-of-the-art Bayesian techniques more accessible and modular.

## The Mathematical Framework of State-Space Models

The core of any dynamical system model in `dynestyx` is a latent, Markovian state $x_t \in \mathbb{R}^{d_x}$. This state represents the "true" condition of the system at time $t$, which is not directly observable. The system begins with an initial condition drawn from a prior distribution $p(x_0)$.

The library supports two primary modes of state evolution: discrete-time and continuous-time. In discrete-time systems, the state at the next time step is a function of the current state, external controls $u_t$, and time:

$$x_{t+1} \sim p(x_{t+1} | x_t, u_t, t)$$

In many scientific applications, however, systems are more naturally described by continuous-time dynamics using Stochastic Differential Equations (SDEs). In this case, the evolution is defined by:

$$dx_t = f(x_t, u_t, t) dt + L(x_t, u_t, t) d\beta_t$$

Here, $f$ represents the deterministic drift of the system, while $L d\beta_t$ captures the diffusion or stochastic noise, where $\beta_t$ is a $d_B$-dimensional Brownian motion. Regardless of whether the internal dynamics are continuous or discrete, the system is observed at discrete intervals. The observation model relates the hidden state to the data $y_t$:

$$y_t \sim p(y_t | x_t, u_t, t)$$

The goal of the researcher is typically twofold: estimate the hidden states $\{x_t\}_{t=0}^T$ (known as filtering or smoothing) and identify the parameters $\theta \in \mathbb{R}^{d_\theta}$ and $\phi \in \mathbb{R}^{d_\phi}$ that govern the evolution and observation processes.

## Separation of Concerns: The Design of Dynestyx

One of the defining features of `dynestyx` is its adherence to the PPL principle of "separation of concerns." In traditional software, the model definition is often tightly coupled with the inference code. If a researcher wants to switch from an Extended Kalman Filter to a Particle Filter, they might have to rewrite large portions of their implementation.

`dynestyx` solves this by decoupling the model specification from the execution strategy. A model is defined using standard Python and NumPyro primitives to describe the joint prior $p(\theta, \phi)$. These parameters are then passed to a `DynamicalModel` object, which encapsulates the physical laws of the system (the initial condition, evolution, and observation model).

Crucially, this model definition is purely declarative—it describes the data-generating process without committing to a specific way of computing the likelihood. The actual computation is handled at "inference time" through the use of effect handlers. For instance, a user can wrap their model in a `Filter` handler to specify that the marginal likelihood should be approximated using a specific algorithm. This allows the same model code to be used for:

1.  **Filtering:** Estimating the current state $p(x_t | y_{1:t})$.
2.  **Smoothing:** Reconstructing past states $p(x_\tau | y_{1:t})$ for $\tau \leq t$ using all available data.
3.  **Simulation:** Generating synthetic trajectories from the model.

## Parameter Identification and Marginal Likelihood

Estimating the parameters $\theta$ and $\phi$ is often the most computationally demanding part of the Bayesian workflow. This process requires calculating the marginal likelihood $p(y_{1:t} | \theta, \phi)$, which involves integrating out all possible hidden state trajectories. Since this integral is usually intractable for non-linear or non-Gaussian systems, it must be approximated.

`dynestyx` approaches this by formalizing a two-step procedure. First, a structure-exploiting algorithm (like a Kalman filter variant or a particle filter) computes an approximation of the marginal likelihood, denoted as $\hat{Z}_{1:T}(\theta, \phi) \approx Z_{1:T}(\theta, \phi)$. Second, this approximation is plugged into a general-purpose parameter inference algorithm.

Because `dynestyx` is built on top of JAX, it can leverage automatic differentiation. This means that if the chosen filtering algorithm is differentiable (such as a Kalman Filter or certain types of Particle Filters), the library can automatically provide gradients of the log-marginal likelihood. This enables the use of powerful gradient-based sampling methods like Hamiltonian Monte Carlo (HMC) or the No-U-Turn Sampler (NUTS), as well as Variational Inference (VI).

The library targets the following objective for parameter estimation:

$$\log p(\theta, \phi) + \log \hat{Z}_{1:T}(\theta, \phi)$$

By combining various filters with various MCMC or VI routines, `dynestyx` unlocks a vast design space of inference strategies.

## Advanced Features: Mixed-Effects and Novel Algorithms

Beyond standard single-trajectory models, `dynestyx` includes support for mixed-effect dynamical systems. These models are essential when dealing with multiple related units—for example, modeling the glucose levels of several different patients. In such cases, some parameters might be shared across the entire population, while others vary per individual.

Using the `plate` primitive in NumPyro, `dynestyx` allows users to define hierarchical models that account for this heterogeneity. The library ensures that these complex structures remain compatible with its suite of filtering and parameter inference tools.

Furthermore, the unified nature of `dynestyx` has allowed the authors to implement combinations of methods that were previously undocumented in the literature. For instance, the library facilitates the use of a Continuous-Discrete Ensemble Kalman Filter (CD-EnKF) in conjunction with gradient-informed MCMC. By providing these "out-of-the-box" combinations, `dynestyx` serves as both a tool for practitioners and a laboratory for researchers to discover more efficient inference compositions.

## Example: Defining a Model in Dynestyx

The following conceptual example illustrates how a user might define a continuous-time dynamical system and perform inference using `dynestyx`. The model describes a simple physical system where the state evolves according to a drift function and is observed through a noisy sensor.

```python
import numpy as np
import jax.numpy as jnp
import numpyro
import numpyro.distributions as dist
import dynestyx as dsx

def model(obs_times, obs_values):
    # 1. Define priors for system parameters
    theta = numpyro.sample("theta", dist.Normal(0.0, 1.0))
    sigma_obs = numpyro.sample("sigma_obs", dist.HalfNormal(1.0))

    # 2. Define the dynamical system components
    def drift(x, u, t, params):
        return -params * x  # Simple linear decay

    def diffusion(x, u, t, params):
        return jnp.ones_like(x) * 0.1

    def observation(x, u, t, params):
        return x  # Identity observation

    # 3. Construct the DynamicalModel object
    dyn_model = dsx.DynamicalModel(
        initial_condition=dsx.InitialCondition(dist.Normal(0.0, 1.0)),
        state_evolution=dsx.ContinuousTimeStateEvolution(drift, diffusion),
        observation_model=dsx.ObservationModel(observation, dist.Normal, sigma_obs),
        params=theta
    )

    # 4. Use dsx.sample to specify the latent state sampling
    # At inference time, an effect handler will decide how to compute the likelihood
    dsx.sample("x", dyn_model, obs_times=obs_times, obs_values=obs_values)

# To perform inference, we pick a filter and an MCMC algorithm
# Here we use an Extended Kalman Filter (EKF) to approximate the likelihood
with dsx.handlers.Filter(dsx.filters.EKF()):
    mcmc = numpyro.infer.MCMC(numpyro.infer.NUTS(model), num_samples=1000, num_warmup=500)
    mcmc.run(jax.random.PRNGKey(0), obs_times, obs_values)
```

In this example, the user defines the physics of the system in a few lines of code. The choice to use the `EKF` for filtering is made at the very end, demonstrating how easy it is to swap one algorithm for another without changing the model's core logic.

## Significance for the Research Community

`dynestyx` represents a move toward a more standardized and modular approach to modeling time-dependent phenomena. Its significance lies in several areas:

*   **Democratization:** It brings advanced, specialized state-estimation algorithms to a wider audience of researchers who are familiar with PPLs but may not have the expertise to implement a Particle Filter from scratch.
*   **Methodological Discovery:** By making different ML estimators and parameter inference routines interchangeable, it allows for the systematic study of which combinations work best for specific classes of problems.
*   **Workflow Efficiency:** It reduces the "friction" of the Bayesian workflow, allowing researchers to iterate on model designs and inference strategies much faster than was previously possible with bespoke code.

By integrating these disparate threads into a single, JAX-backed framework, `dynestyx` provides a powerful foundation for the next generation of Bayesian dynamical systems research.
