## Addressing the Evidence-Substrate Mismatch in Biomedical QA

Biomedical question answering (QA) represents a unique challenge for artificial intelligence. Unlike general-domain QA, answering a biomedical query often requires navigating a fragmented landscape of information sources. A researcher might need to synthesize findings from millions of scientific abstracts, resolve ambiguous gene symbols in a curated database, or extract quantitative expression levels from high-throughput biological atlases. 

Current systems typically rely on Retrieval-Augmented Generation (RAG). In a standard RAG pipeline, a Large Language Model (LLM) is paired with a retrieval system that searches a text corpus—most commonly PubMed—to find relevant context. While effective for many tasks, this "one-size-fits-all" approach suffers from what researchers call evidence-substrate mismatch. This occurs when a system tries to answer a question using textual passages when the necessary evidence actually resides in a structured database or a numerical atlas. For example, a textual abstract might mention that a gene is expressed in the liver, but a biological atlas provides the precise, quantitative measurement required to compare it against other tissues.

To address these limitations, a new framework called BioHarness has been developed. It introduces a substrate-aware approach that adaptively selects and assembles evidence from heterogeneous sources. Rather than treating all retrieval as a text-search problem, BioHarness recognizes that different questions require different "substrates"—literature, curated knowledge, or structured measurements—and routes them accordingly.

## Staged Literature Evidence Assembly

The first step in the BioHarness pipeline is the assembly of literature-based evidence. While text is not the only source of truth, it is often the most accessible starting point. BioHarness improves upon standard retrieval by using two complementary views to search a corpus of 20 million PubMed abstracts.

First, the system uses the original question to maintain lexical precision. Second, it employs a "Hypothetical Abstract Rewrite" view. In this step, the LLM generates a short, PubMed-style hypothetical abstract that might contain the answer. This rewritten query often aligns more closely with the actual structure of scientific literature than the raw question does, improving the recall of relevant documents.

Once potential passages are retrieved from both views, they are merged and de-duplicated. However, retrieving relevant text is only half the battle. To ensure high precision, BioHarness employs a specialized reranker. This reranker assesses the retrieved snippets against the original question, ensuring that only the most pertinent information is included in the initial evidence context. This literature-centric path is designed to be fast and efficient, serving as the "default" route for questions that can be answered through scientific prose alone.

## Grounded Cascade Control

A key innovation of BioHarness is its use of a grounded cascade controller. Not every question requires a complex search through multiple databases. Executing a full multi-step reasoning chain for every query would be computationally expensive and potentially introduce noise. 

The cascade controller acts as an intelligent router. It first attempts to generate a draft answer, denoted as $a^{(0)}$, based solely on the retrieved literature evidence. To decide whether this draft is sufficient, the controller evaluates two signals:
1.  **Confidence Score:** The system calculates a confidence score based on the probability of the tokens generated in the draft answer.
2.  **Evidence Grounding Check:** The system checks if the draft answer is explicitly supported by the retrieved text. If the answer involves a specific gene or chemical, BioHarness verifies that the term appears in the retrieved titles or abstracts.

If the confidence score exceeds a threshold (e.g., $0.7$) and the grounding check is successful, the system terminates the process and returns the draft answer. If the evidence is deemed uncertain, weakly grounded, or mismatched—such as when a question asks for numerical data not found in the text—the controller escalates the query to the "REPL-style" evidence repair loop.

## The REPL-style Evidence Repair Loop

When the initial literature path fails, BioHarness enters a Read-Eval-Print Loop (REPL) for executable evidence repair. In this environment, the LLM acts as an agent capable of performing operations across two distinct structured substrates: the Biomedical Tool Layer and the Atlas Evidence Layer.

*{fig:bioharness-architecture}: The BioHarness architecture. The process starts with literature assembly (a), passes through a grounded sufficiency control (b), and if necessary, escalates to a REPL loop for executable evidence repair (c).*

### The Biomedical Tool Layer
Biomedical entities often have multiple names, synonyms, or deprecated identifiers. For instance, the gene symbol "AGTIL" is an obsolete alias for "ASIP". A literature-only search might fail if the retrieved text uses one version while the question uses another. The tool layer provides symbolic grounding, allowing the model to normalize symbols, look up identifiers in databases like HGNC or UniProt, and traverse biological ontologies. This resolves ambiguity at the identity level.

### The Atlas Evidence Layer
Some questions require data that is fundamentally non-textual. Biological atlases contain quantitative measurements, such as gene expression levels across different cell types or tissues. BioHarness uses an Atlas Router to identify if a query requires these structured measurements. If it does, the system generates code to query the atlas namespace, fetching specific objects that contain metadata, quantitative values, and provenance. This allows the system to perform operations like, "Find the tissue with the highest expression of gene X," which might not be explicitly stated in any single PubMed abstract.

Through the REPL loop, the model constructs a stateful "evidence trace." This trace records the actions taken (e.g., tool calls, atlas queries) and the observations received. This history is eventually compressed into an "evidence pack" that informs the final answer generation.

## Performance and Efficiency Results

BioHarness was evaluated across a unified benchmark of 19,302 questions spanning eight datasets, including clinical, literature, and genomics tasks. The system achieved a pooled score of $71.0$, surpassing traditional RAG baselines and even specialized tool-augmented models like GeneGPT, which scored $65.9$.

One of the most significant findings was the system's efficiency. Many advanced RAG methods, such as those using complex graph-based retrieval, achieve higher accuracy but at the cost of extreme latency and high token consumption. BioHarness, however, occupies the "efficient frontier" of the score-compute trade-off.

![efficiency-analysis](https://paper-assets.alphaxiv.org/figures-normalized/figures/2606.19396v1/figure/efficiency.png)
*{fig:efficiency-analysis}: Efficiency analysis showing the trade-off between score and latency. BioHarness (Ours) achieves the highest performance while maintaining a moderate computational cost compared to graph-based and agentic methods.*

The ablation studies provided further insight into why the system performs well:
- **Iterative Reasoning:** Removing the REPL loop led to the largest performance drop, particularly in tasks requiring the aggregation of multiple pieces of evidence.
- **Tool Integration:** The Biomedical Tool Layer was essential for genomics tasks (like GeneTuring), where resolving gene aliases is a frequent bottleneck.
- **Cascade Control:** While disabling the cascade didn't significantly lower the final score, it increased latency by over 7 times for simple questions, proving that the "fast path" is vital for practical deployment.

## Understanding the Atlas Contribution

The inclusion of biological atlases provided a unique advantage in specific domains. In cases where literature evidence was sparse or purely qualitative, atlas-derived measurements allowed the system to recover correct answers. For example, in expression-related tasks, the system correctly identified tissue distributions for genes like GABRA4 and LRRC66 by querying structured data when scientific abstracts were insufficient.

However, the researchers also noted a "degradation mode" where atlas data could sometimes introduce noise. If an atlas query returned broad expression signals for a very common protein, it could dilute the precision of specific literature-derived answers. This highlights the importance of the router-gated access: the atlas is a powerful substrate, but it must be invoked only when the query type and literature insufficiency warrant it.

## Scaling and Robustness

BioHarness was also tested across different model sizes, ranging from small 0.8B parameter models to large 122B parameter models. The results showed that BioHarness consistently outperformed baseline methods at every scale. While larger models generally perform better across the board, the gap between BioHarness and other RAG techniques remained significant. This suggests that the benefits of substrate-awareness are structural and cannot be easily replicated simply by using a larger, more powerful LLM.

## Significance for the Biomedical Field

The development of BioHarness marks a shift from uniform RAG pipelines to adaptive, substrate-aware systems. By recognizing the fundamental differences between textual narratives, curated identities, and quantitative measurements, BioHarness provides a more robust framework for biomedical discovery.

For researchers, this means a tool that can not only read papers but also "understand" that a gene name might be outdated and "know" how to check a database for the most recent quantitative data. The system’s ability to provide grounded, evidence-backed answers while maintaining computational efficiency makes it a viable candidate for real-world applications in clinical decision support and genomic research. Future work in this area is expected to expand the number of integrated substrates and further refine the logic used to determine when evidence is truly "sufficient."
