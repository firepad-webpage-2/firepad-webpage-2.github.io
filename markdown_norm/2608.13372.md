## Integrating Communication, Computation, and Physical Processes

In modern industrial environments, the convergence of wireless connectivity and intelligent automation is creating a new class of cyber-physical systems. These systems, ranging from autonomous mobile robots to automated factory inspection lines, rely on a seamless pipeline: sensing data from the physical world, transmitting it over a network, processing it at the edge using artificial intelligence, and returning a decision to an actuator. However, in these closed-loop applications, the value of a decision is not solely determined by its accuracy. A decision must also be timely, arriving before the physical process renders it obsolete.

![fig-1-a-process-aware-factory-inspection-pipeline-where-deadlines-are-determined-by-conveyor-speed](https://paper-assets.alphaxiv.org/figures-normalized/figures/2608.13372v1/Fig1_mockup3.png)

A critical challenge in these environments is that the deadline for a task is often dynamic and dictated by the state of the physical process itself. For example, in a conveyor-based sorting system, the time window for an inspection decision shrinks as the conveyor speed increases. Existing approaches often optimize these domains—radio, computation, and process control—in isolation. A network controller might optimize for throughput, while an edge controller optimizes for inference latency, and a production manager sets the conveyor speed. This "siloed" optimization often fails to account for the cross-layer dependencies, leading to scenarios where a system is either wasteful or unable to meet operational requirements. This research introduces a framework for **Process-Aware Co-Adaptation (PACE)** that integrates telemetry from the radio, edge, sensing, and physical process layers to make coordinated resource allocation decisions.

## The Limitation of Siloed Network Management

Current network management strategies, including those enabled by Open RAN (O-RAN), provide significant programmability for the radio layer. O-RAN architectures allow for near-real-time RAN Intelligent Controllers (RICs) to adjust parameters such as resource block allocation or modulation schemes based on radio channel conditions. Similarly, edge orchestration tools can adjust central processing unit (CPU) or graphics processing unit (GPU) quotas based on computational load.

Despite these advancements, the missing link is the "process context." From the perspective of the network, a packet containing an image for defect detection is just bits to be delivered. The network does not know if that image must be processed within 100 milliseconds or 500 milliseconds to be useful for the sorting robot. If the conveyor belt slows down, the deadline relaxes, potentially allowing the network to save power or bandwidth by reducing its allocation to that specific task. Conversely, if the belt speeds up, the deadline tightens, requiring immediate resource shifts across the entire pipeline. 

The authors argue that "co-design"—setting up a system for a specific fixed operating condition—is insufficient for the dynamic nature of industrial production. Instead, they propose "co-adaptation," which involves the runtime adjustment of cross-layer operating points as both the infrastructure (e.g., network congestion, server load) and the process (e.g., production rate) evolve.

## The PACE Framework: A Cross-Layer Approach

The Process-Aware Co-Adaptation Engine (PACE) is designed to act as a higher-level controller that synthesizes signals from disparate domains to manage the end-to-end performance of a closed-loop task. The architecture, shown below, emphasizes the integration of multi-domain observations to guide coordinated actions.

![fig-2-the-pace-architecture-showing-the-closed-loop-cycle-of-observation-exploration-evaluation-and-selection](https://paper-assets.alphaxiv.org/figures-normalized/figures/2608.13372v1/Fig2_mockup3.jpg)

PACE gathers data from four main sources:
1.  **Radio State:** Metrics like Physical Resource Block (PRB) usage and transfer delays from the O-RAN stack.
2.  **Edge State:** CPU utilization and inference queueing delays from the compute server.
3.  **Sensing and Process State:** Current image resolution settings and physical variables like conveyor speed $v$, which define the available time window for a decision.
4.  **Application Outcome:** Whether the final decision was correct and whether it arrived before the deadline.

By combining these signals, PACE can diagnose the root cause of a failure. For instance, if a decision is late, PACE can determine if the delay was caused by radio congestion, a saturated edge server, or a physical process that simply moved too fast for the current resource allocation.

### Multi-Objective Application Metrics

To evaluate how well a configuration serves the industrial task, the paper defines three key metrics that move beyond traditional throughput or latency:

*   **Correct-on-time rate:** This is the ratio of inspection cycles where the classification was both correct and delivered before the deadline. It ensures that neither accuracy nor speed is sacrificed.
*   **Production Goodput:** Measured in parts per minute, this represents the volume of useful work performed by the system.
*   **Production Efficiency ($\eta$):** This metric quantifies how much "good" work is done per unit of infrastructure resource consumed. It is defined as:

$$\eta = \frac{\text{Production Goodput}}{\text{Uplink Allocation} \times \text{Edge CPU Quota}}$$

Here, the denominator accounts for the cost of the radio slice and the compute quota. Maximizing this efficiency prevents the controller from simply "throwing more resources" at a problem when a more efficient combination (like reducing image resolution to save both transmission and compute time) might suffice.

## Experimental Setup and Digital Twin Integration

To test the PACE framework, the researchers developed a full-stack factory inspection environment that combines high-fidelity physics simulation with real-world communication and compute stacks. 

The physical process was modeled using **NVIDIA Isaac Sim**, a digital-twin platform that simulated a conveyor belt moving parts past a camera toward a sorting robot. The communication path utilized **OpenAirInterface (OAI)** to create a functional 5G O-RAN link, controlled by a **FlexRIC** controller to manage radio resources in real-time. The visual inference was performed by a **YOLO-based detector** running on an edge server, trained to identify defects on metallic surfaces.

![fig-3-the-experimental-testbed-integrating-nvidia-isaac-sim-oai-based-5g-and-edge-inference-components](https://paper-assets.alphaxiv.org/figures-normalized/figures/2608.13372v1/Fig3_mockup3.png)

The experiment explored a multi-dimensional design space consisting of 960 distinct operating points. These points represented different combinations of uplink PRB shares (10% to 90%), edge CPU quotas (1 to 8 cores), image resolutions (from 320x180 to 1280x720), and conveyor speeds ($v$ from 0.5 to 2.0 m/s). This comprehensive mapping allowed the researchers to observe how the optimal resource configuration shifted as the physical process accelerated.

## Key Findings: The Necessity of Joint Adaptation

The results of the experimental sweep highlights two major insights regarding the management of industrial cyber-physical systems.

### 1. The Shifting Bottleneck
The "best" configuration is highly sensitive to the process state. At a low conveyor speed of $v = 0.5 \text{ m/s}$, the system could achieve high efficiency with minimal radio and compute resources. However, as the speed increased to $v = 1.5 \text{ m/s}$, the time available for the sensing-to-actuation pipeline decreased significantly. To maintain a high correct-on-time rate, the system had to shift to a configuration with higher PRB allocation and more CPU cores. 

Crucially, the research found that adapting only one parameter (e.g., just the radio slice or just the CPU quota) was far less effective than joint adaptation. For example, if the network is the bottleneck, adding more CPU cores to the edge server will not improve the end-to-end timing. PACE's ability to adjust all layers simultaneously allowed it to find "sweet spots" that isolated-layer controllers would miss.

### 2. Efficiency Gains vs. Over-Provisioning
The study compared PACE's joint adaptation strategy against a "fixed high-resource" baseline—a common approach in industrial settings where resources are provisioned for the worst-case scenario. While the high-resource baseline could handle fast conveyor speeds, it was extremely inefficient at lower speeds, wasting approximately 35 times more resources than the PACE-optimized configuration. Conversely, joint selection achieved efficiencies of 0.96 at low speeds, even while maintaining high performance.

### 3. Rapid Convergence with Surrogate Models
Since searching through 960 configurations in a live factory environment is not feasible, the researchers evaluated how quickly a controller could "learn" the best operating points. Using surrogate modeling techniques like **Upper Confidence Bound (UCB)** and **Thompson Sampling** with tree-based ensembles, they demonstrated that the system could identify configurations providing 90% of the maximum possible efficiency within just 100 evaluations (roughly 10% of the total design space). This suggests that PACE can be effectively deployed even in environments where the optimal operating map is not known in advance.

## Significance for Future Industrial Systems

This research underscores that for wireless networks to be truly effective in industrial automation, they must be "process-aware." The O-RAN paradigm provides the necessary hooks for radio programmability, but it requires a coordinating intelligence like PACE to translate physical production goals into specific radio, compute, and sensing configurations.

The implications of this work extend to several areas:
*   **Flexible Manufacturing:** As factories move toward more flexible, modular layouts, the ability to dynamically adapt to different production rates and tasks becomes essential.
*   **Shared Infrastructure:** In scenarios where multiple industrial applications share the same 5G network and edge server, efficiency is paramount. PACE ensures that each application only consumes the resources it needs to meet its specific process deadline.
*   **Digital Twin Utility:** The work demonstrates how physics-based digital twins can be used to "rehearse" and optimize configurations before they are applied to the physical factory floor, reducing the risk of downtime.

By moving beyond siloed optimization and embracing a cross-layer, process-driven approach, industrial systems can achieve a higher level of reliability and efficiency, fully leveraging the potential of O-RAN and edge intelligence.
