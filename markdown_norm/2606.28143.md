## Introduction to Symbolic Control and Robustness

The design of controllers for complex cyber-physical systems (CPS)—such as autonomous vehicles, smart grids, and robotic explorers—requires high levels of reliability. One established methodology for achieving this is Abstraction-Based Controller Design (ABCD). In this approach, the continuous state space of a physical system is discretized into a finite set of "symbolic" states. By doing so, designers can use formal verification tools to synthesize a controller that is mathematically guaranteed to satisfy specific requirements, often expressed in Linear Temporal Logic (LTL).

However, real-world systems are rarely "nominal." They are subject to modeling errors, external disturbances, and sensor noise. A controller that works perfectly on a simplified, disturbance-free model might fail when applied to the actual hardware. To address this, researchers focus on "robust" symbolic control. Traditional robust methods usually start with a predefined set of possible disturbances and design a controller to handle the worst-case scenario within that set. While effective, this can be overly conservative, leading to controllers that are too cautious or even failing to find a controller when one might exist.

This work shifts the perspective. Instead of designing for a fixed disturbance, it asks: *Given a controller already synthesized for a nominal system, what is the maximum perturbation it can withstand while still satisfying its specification?* By introducing "specification-aware" robustness margins, the authors provide a way to quantify the resilience of symbolic controllers more precisely than previous generic methods.

## System Modeling and Symbolic Abstractions

To understand how these margins are calculated, we first define the mathematical models used. The "concrete" or physical system $\Sigma$ is modeled in discrete time as:
$$
x_{k+1} = f(x_k, u_k, d_k)
$$
where $x$ represents the state, $u$ is the control input, and $d$ is a disturbance. In a formal context, this is viewed as a transition system $S(\Sigma) = (X, X_0, U, \Delta)$, where $\Delta$ describes all possible next states for a given state and input.

When we consider a perturbed system $\Sigma_\varepsilon$, the dynamics change to include an additional uncertainty ball:
$$
x_{k+1} \in f(x_k, u_k, d_k) + B_{\varepsilon(x_k, u_k)}(0)
$$
Here, $B_{\varepsilon(x_k, u_k)}(0)$ is a ball of radius $\varepsilon(x_k, u_k)$ centered at zero. This $\varepsilon$ represents the unknown perturbation we want to quantify.

In ABCD, we create a symbolic abstraction $S_d(\Sigma) = (X_d, X_{0d}, U_d, \Delta_d)$. This abstraction is a finite-state machine where each state represents a "cell" in the discretized state space. A critical tool in this process is the "predecessor operator" $Pre_{\Delta}(Z)$, which identifies all state-input pairs that are guaranteed to end up inside a target set $Z$:
$$
Pre_{\Delta}(Z) = \{(q, v) \in X_d \times U_d \mid \Delta(q, v) \subseteq Z\}
$$
The controller synthesis is essentially a series of calculations using this $Pre$ operator until a "fixed point" (a stable set of states) is reached.

## Defining Specification-Aware Robustness Margins

The core contribution of this work is the definition of the robustness margin $\gamma(q, v, L)$. This margin represents the largest admissible perturbation $\varepsilon$ such that the system's behavior remains consistent with the nominal requirements.

Most previous methods used a generic margin, often denoted as $\eta(q, v, \Delta_d(q, v))$, which only ensures that the perturbed system stays within the immediate "symbolic next-step" defined during abstraction. This paper argues that this is too restrictive. Instead, the margin should depend on the *specification* (the goal of the controller).

![illustration-of-robustness-margins-in-the-state-space](https://paper-assets.alphaxiv.org/figures-normalized/figures/2606.28143v1/x2.png)
*{fig:illustration-of-robustness-margins-in-the-state-space}: Visual comparison of the generic abstraction-based margin $\eta$ and the new specification-aware margin $\gamma$. The new margin is determined by the distance to the boundary of the relevant target sets $L$, allowing for larger disturbances.*

For a given state $q$ and input $v$, and a collection of sets $L = \{Z_0, \dots, Z_m\}$ generated during the controller synthesis, the margin is defined as:
$$
\gamma(q, v, L) = \eta(q, v, I(q, v, L))
$$
where $I(q, v, L)$ is the intersection of all target sets that $(q,v)$ was intended to reach:
$$
I(q, v, L) = \bigcap_{Z_i \in L, (q,v) \in Pre_{\Delta_d}(Z_i)} \pi_X(Z_i)
$$
This construction ensures that as long as the disturbance $\varepsilon(x,u)$ is smaller than $\gamma$, the symbolic $Pre$ operator behaves identically for both the nominal and the perturbed system. This "sharpness" allows the designers to know exactly when a controller will remain valid.

## Robustness Across Different LTL Fragments

The researchers apply this logic to four fundamental types of control objectives, which serve as the building blocks for more complex LTL formulas.

### 1. Safety Specifications
A safety specification requires the system to stay within a "safe" region $X_T$ forever. The controller is synthesized by finding the largest set of states that can keep the system inside $X_T$. The robustness margin here simplifies to the distance between the perturbed reachable set and the boundary of the entire domain of the controller $dom(C_d)$.

### 2. Reachability Specifications
Reachability requires the system to reach a target set $X_T$ within a finite amount of time. Synthesis involves "layering" the state space based on how many steps it takes to reach the target. The robustness margin $\gamma$ is then determined by the system's ability to transition into a "closer" layer. Specifically, it is $\eta(q, v, \pi_X(Z_{j_L(q)-1}))$, where the subscript $j_L(q)-1$ represents the next layer toward the goal.

### 3. Persistence and Recurrence
Persistence means "eventually stay forever" in a set, while recurrence means "visit infinitely often." These require nested fixed-point algorithms. The authors show that even for these complex nested iterations, a specific list of intermediate sets $L$ can be used to calculate a single robust margin that guarantees the controller will still achieve the high-level goal despite disturbances.

## Theoretical Comparison and Numerical Results

The paper mathematically proves that the specification-aware margin $\gamma$ is always greater than or equal to the standard abstraction-based margins. To demonstrate the magnitude of this improvement, they analyzed a classic "double integrator" system (modeling basic motion) under a safety specification.

As shown in Table II of the paper, the new margins are between 7 and 54 times higher than previous bounds. Interestingly, the study found that making the discretization finer (increasing resolution) actually *increases* the specification-aware margin, whereas it usually *decreased* the generic margins. This suggests that high-resolution symbolic models are actually more robust when using the correct metrics.

## Application to Complex Robotic Tasks

The framework was also tested on a nonlinear mobile robot model. The task was a combination of persistence and recurrence: the robot had to avoid obstacles while visiting three specific regions ($C_1, C_2, C_3$) in a specific order, infinitely often.

![robot-trajectories-under-maximum-disturbance](https://paper-assets.alphaxiv.org/figures-normalized/figures/2606.28143v1/combined_specification.png)

In this example, the robot successfully navigated the environment despite disturbances. The authors also simulated a case where the disturbance *exceeded* the calculated margin $\gamma$. In that instance, the robot failed to enter the target regions, confirming that the calculated margin is indeed a tight upper bound for the controller's reliability.

## Conclusion and Significance

By moving away from fixed-disturbance design and focusing on the inherent robustness of nominal controllers, this work provides a more flexible way to verify cyber-physical systems. The key insight is that robustness is not a single number for a system, but rather a value that depends on what the system is trying to achieve.

The specification-aware robustness margins provide three main advantages:
1.  **Reduced Conservatism:** They allow for much larger disturbances than previous methods, meaning systems can operate in harsher environments without needing a complete redesign.
2.  **Precision:** The margins provide a sharp threshold for when a controller will fail.
3.  **Efficiency:** The margins are computed using the sets already generated during standard controller synthesis, meaning they add little computational overhead.

This research establishes a formal link between the logic of the specification and the physical resilience of the system, paving the way for more reliable autonomous systems that can handle the uncertainties of the real world.
